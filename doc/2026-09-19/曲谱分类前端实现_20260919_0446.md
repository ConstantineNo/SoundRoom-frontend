# 曲谱分类前端实现与验证

日期：2026-09-19。代码基线：4f4951e1d45f8841cceec9549d8bcfa199012e75；共享 Docs 已从 257415d 快进到 736ac92。

## 实现

- `/library`：公开/我的曲谱，笛调 → 指法 → 去重曲目；搜索、分页、待归类/待复核、同一组合覆盖全曲过滤。数量取服务端聚合，不对不同分类相加。
- 列表按页补取详情（最多12条），展示真实方案名、命中段名及逐方案跟练状态；详情失败时不冒称无谱。局部命中明确显示换笛/换指法及未确认段。
- 快速登记：曲名、原调、规范或原文指法；不要求附件。候选独立请求，展示依据和音域限制，必须主动采用或人工确认；可直接保存待归类。改变依据撤销尚未保存的确认。
- `/scores/:scoreId`：曲目信息/标签编辑、替代方案新增、默认方案、方案完整性、按序分段增删/移动。保留已有段ID和A→B→A顺序；只提交契约允许的字段。新增转调段默认以段落调性为依据，不悄悄套用全曲原调。
- 删除默认方案前必须选择替代默认，不能删除最后一套；删除提示说明曲目资料保留。
- 附件支持 PNG/JPEG、PCM WAV、UTF-8 ABC，20 MiB 上限；机器谱必须关联方案。使用带Bearer的资料端点取得Blob；收起、刷新、账号切换及页面卸载释放URL，不使用匿名/uploads。
- 公开/撤回、复制私有副本；所有者依据/auth/me的id与owner.id识别。公开前说明附件独立权限。
- JSON envelope、Bearer、ETag/If-Match、创建意图幂等键均接入。网络重试复用同一意图键；412保留草稿、刷新最新详情，禁止直接覆盖；409过期候选提示重新推算或人工确认。
- 按方案显示跟练能力；当前后端未就绪时禁用入口。不将图片、音频或stored机器谱视为可跟练，不调用未就绪A04。
- 手机和桌面响应式布局；保留原项目其他页面，未改造旧编辑器、练习工作台和播放列表协议。

## 本地启动

Node >= 20.19（本次使用24.20.0）。安装依赖后运行 `npm run dev`，访问 `/library`。

Vite默认将同源 `/api` 转发到 `http://163.192.34.11` 并移除前缀。可在 `.env` 设置 `SOUNDROOM_API_TARGET=http://127.0.0.1:8000`；目标只填后端origin，不带/api。生产部署仍需配置同源API反代，当前测试服务是HTTP，不应让HTTPS页面直连HTTP接口。
