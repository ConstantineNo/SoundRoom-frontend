# 组件版本 CI 接入

根 `VERSION` 为组件版本唯一来源；初始占位 `0.0.0` 在首次 feat 推送后自动变为 `0.1.0`。
当前规则见 [SoundRoom 版本规则](http://gitlab.1to.top/jumomo/SoundRoom_Docs/-/blob/main/capabilities/component-versioning/rules.md)。
操作流程见 [CI/CD](http://gitlab.1to.top/jumomo/SoundRoom_Docs/-/blob/main/capabilities/component-versioning/cicd.md)。

- 提交使用 `feat:`、`fix:` 等类型；不明确的提交按 fix 处理。需要独立验证的 chore/test/build 改动加 `Version-Bump: fix`；首个正式版加 `Version-Bump: major`。
- 不手工更新 VERSION，不使用跳过 CI 的提交标记。每次推送后等待 Component version 工作流成功，再 `git pull --ff-only` 获取机器人版本提交；有本地开发时按正常合并流程保留修改。
- 所有分支 push 自动回写；PR/标签仅验证，标签应指向已成功版本化的提交。禁止依赖 force push 更新版本。
- 重跑同一 push 复用版本；并发普通推送自动重试，权限/保护规则阻止写入时显式失败，不绕过保护。
- GitHub 内置 GITHUB_TOKEN 只在 refresh job 有 contents:write；不配置个人 token。其回写不会触发第二次 push workflow，构建在本工作流消费回写后的精确 commit。
- 本仓 scripts/versioning 自包含，不需要在 CI 拉取私有 Docs 或 AED。
- 本地验证：`python3 -m unittest discover -s scripts/versioning -p 'test_*.py' -v`。
- 测试沙箱位于忽略的 `.version-tests/` 内。CI 运行结果和版本发布不能替代业务测试或部署验收。

前端构建：`npm ci && npm run build && node scripts/versioning/check-build.mjs`。
构建注入 `__SOUNDROOM_VERSION__` 并生成 `dist/version.json`。package.json/package-lock.json 的 version 为 npm 包元数据，不作为运行组件版本；带字母后缀的组件号不写入 npm SemVer 字段。
